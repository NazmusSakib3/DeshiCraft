# Deployment guide

DeshiCraft is deployed as three pieces:

| Piece    | Host          | Notes |
|----------|---------------|-------|
| Database | MongoDB Atlas | Free M0 cluster is enough for a demo |
| API      | Render        | Node web service (see `render.yaml`) |
| Frontend | Vercel        | Static Vite build (see `client/vercel.json`) |

**Order:** Atlas → Render → Vercel → set `CLIENT_URL` on Render → seed production DB.

---

## 1. MongoDB Atlas

You must create the cluster yourself — credentials are never committed to this repo.

1. Sign up at [cloud.mongodb.com](https://cloud.mongodb.com) and create a free **M0** cluster.
2. **Database Access** → add a user (username + password). Save the password.
3. **Network Access** → **Add IP Address** → **Allow Access from Anywhere** (`0.0.0.0/0`). Required so Render can reach Atlas.
4. **Database** → **Connect** → **Drivers** → copy the connection string.
5. Replace `<password>` and set the database name to `deshicraft`:

   ```
   mongodb+srv://USER:PASS@cluster0.xxxxx.mongodb.net/deshicraft?retryWrites=true&w=majority
   ```

6. Keep this URI for Render env vars and the one-time production seed below.

For local reference only, copy `server/.env.example` → `server/.env` and set `MONGO_URI` there. **Do not commit `.env`.**

---

## 2. API on Render

1. Push this repo to GitHub (include the latest `render.yaml`).
2. Render → **New** → **Blueprint** → select `NazmusSakib3/DeshiCraft`.
3. The blueprint builds from the **repo root** (`npm ci` + `npm run build --workspace @deshicraft/server`). Do **not** set Root Directory to `server` in the dashboard — that breaks `npm ci` (no lockfile in `server/`).
4. Set environment variables marked `sync: false`:

   | Variable | Value |
   |----------|--------|
   | `MONGO_URI` | Atlas URI from step 1 |
   | `CLIENT_URL` | Vercel URL (e.g. `https://deshicraft.vercel.app`) — use a placeholder until Vercel is live, then update and redeploy |
   | `SEED_ADMIN_EMAIL` | e.g. `admin@deshicraft.local` |
   | `SEED_ADMIN_PASSWORD` | Strong password for the seeded admin |

   JWT secrets are auto-generated by the blueprint.

5. Deploy. Confirm: `GET https://<service>.onrender.com/api/health` → `{"status":"ok",...}`.
6. **Free tier:** spins down when idle; first request may take 30–60 seconds.

---

## 3. Frontend on Vercel

1. Vercel → **Add New Project** → import `NazmusSakib3/DeshiCraft`.
2. **Root Directory:** `client` (Framework: Vite; Output: `dist`).
3. `client/vercel.json` installs from the monorepo root (`cd .. && npm ci`) then builds in `client`.
4. Environment variable (Production):

   | Variable | Value |
   |----------|--------|
   | `VITE_API_URL` | `https://<your-render-service>.onrender.com/api` |

5. Deploy and note the Vercel URL.

---

## 4. Wire CORS and cookies

- API CORS is restricted to `CLIENT_URL` (`server/src/app.ts`).
- Refresh token cookie: `httpOnly`, `SameSite=None`, `Secure` in production (`server/src/controllers/authController.ts`).
- Both hosts must use HTTPS (Vercel and Render provide TLS by default).
- After Vercel deploy: set `CLIENT_URL` on Render to the **exact** Vercel origin (no trailing slash), then redeploy/restart the API.

---

## 5. Seed production data

Run once from your machine with the **Atlas** URI:

**PowerShell:**

```powershell
cd "f:\New Project\deshicraft"
$env:MONGO_URI="mongodb+srv://USER:PASS@cluster0.xxxxx.mongodb.net/deshicraft?retryWrites=true&w=majority"
$env:SEED_ADMIN_EMAIL="admin@deshicraft.local"
$env:SEED_ADMIN_PASSWORD="YourStrongPassword"
npm run seed --workspace @deshicraft/server
```

**bash:**

```bash
cd deshicraft
MONGO_URI="mongodb+srv://USER:PASS@.../deshicraft" \
SEED_ADMIN_EMAIL="admin@deshicraft.local" \
SEED_ADMIN_PASSWORD="YourStrongPassword" \
npm run seed --workspace @deshicraft/server
```

## Alternative: single-host Docker

The API ships with a `Dockerfile`. You can build and run it anywhere that hosts containers:

```bash
docker build -t deshicraft-api ./server
docker run -p 5000:5000 --env-file server/.env deshicraft-api
```
